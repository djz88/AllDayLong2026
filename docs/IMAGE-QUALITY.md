# AllDayLong 2026 – Image quality and limitations

This document describes the actual image properties of the currently distributed version in `../images/`. Instructions for future regeneration are provided in `PROMPT-INSTRUCTIONS.md`.

## Source images

The historical reference images are stored in `original-AllDayLong/`.

- Eight JPEG images at 1280 × 800.
- The original images use a 16:10 aspect ratio.
- The current output wallpapers use a 16:9 aspect ratio.
- The conversion therefore includes adapting the composition to the 3840 × 2160 target format.

According to the production notes, the reconstruction working assets were AI illustrations at 1672 × 941. These intermediate files are not the historical JPG files stored in `original-AllDayLong/` and are not included in this package.

## Current output

- Eight 24-bit PNG files at 3840 × 2160.
- sRGB color space and a 16:9 aspect ratio.
- Clean reconstruction using Lanczos interpolation and localized edge enhancement around the clouds and planet, without global sharpening or added grain.
- Time-linked local deformations include the planet position, the flow of the left-side ionization filaments, the shape of the golden loop, light points, and cloud parallax.
- New subtle light cores and sparse stars are rendered directly on the final 4K raster rather than enlarged from the original image.

## Metadata for this run

- **Model:** OpenAI — a generative image model used to create the source illustrations. The final 4K version was not generated by a new model; it was reconstructed from earlier images.
- **Model version:** Unknown — the tool did not provide an exact image-model identifier.
- **Tools:** OpenAI `image_gen` for the source illustrations; Python and Pillow for reconstruction, geometric transformations, and final export.
- **Seed:** Not recorded (`null`). Deterministic reproduction of the original generation is not guaranteed.
- **Input resolution:** 1280 × 800 px for the historical reference illustrations; their author is unknown, and they are not AI-generated.
- **Output resolution:** 3840 × 2160 px (4K UHD), 24-bit RGB PNG, 16:9, eight separate images.
- **Date:** November 1, 2026, according to the metadata of the resulting ZIP archive.
- **Post-processing:**
  - Enlarging source illustrations with Lanczos interpolation.
  - Localized enhancement of cloud and planet edges without aggressive global sharpening.
  - Removal of synthetic grain and unwanted doubled light contours from the previous version.
  - Time-linked geometric deformation: subtle planet drift, cloud parallax, ionization-stream deformation, changes to the golden orbital curves, and movement of light points.
  - Addition of subtle light cores and stars directly on the final 3840 × 2160 raster.
  - Preservation of clean color gradients, subtle bloom, and visual continuity between daily states.
- **Known deviations:**
  - The output PNG files are 4K, but the base scene was not generated natively at 4K.
  - Neural super-resolution such as Real-ESRGAN was not used because the required model weights were unavailable.
  - Fine cloud and planet detail is limited by the resolution of the original illustrations.
  - Working images created by the generative model do not have perfectly identical geometry, so blending may reveal minor doubled contours.
  - Movement is simulated between static frames; this is not a true time-based animation.
  - The original seed and exact generative-model version cannot be reconstructed retrospectively.

## Limitations

- The base was reconstructed but **not regenerated as a complete native 4K render**.
- This is not neural AI super-resolution either: pretrained SR model weights were unavailable for this run and could not be downloaded.
- Increasing the pixel count cannot guarantee new authentic detail in the clouds; native 4K detail is primarily present in the newly added light points.
- Minor doubled contours may appear during blending because the underlying images do not have perfectly identical geometry.

These limitations apply to the current files in `images/`. Goals for a possible future full regeneration are documented separately in `PROMPT-INSTRUCTIONS.md`.
